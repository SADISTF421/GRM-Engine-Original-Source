# Исходная база GRM: исследование

Исследовательский Git-снимок `engine-src.rar`, не игровой патч и не подтверждённая копия установленной игры. История Git создана при импорте. Движковые файлы побайтно сохранены без правок.

## Происхождение и состав

- Архив: SHA-256 `0d703f4e4fea99d9aebdd51f7c71ed894b9e1f0b606b7f9512acc47595614d97`. Тест UnRAR успешен; размеры 28 335 файлов сверены с оглавлением архива.
- В Git включено 25 879 файлов архива: `trunk`, `SDK`, `libraries`, `Resources`, скрипты сборки и `binaries` кроме PDB. Вложенные архивы сохранены.
- Исключены 2 456 файлов: `intermediate/` (промежуточные результаты, включая вложенный архив) и `binaries/*.pdb`. Они остаются в оригинальном архиве; сохраняйте его. В частности, `binaries/xrGame.pdb` может понадобиться при анализе соответствующей DLL. Это не полное воспроизведение оригинального архива.
- `SHA256_TRACKED_ARCHIVE_FILES.tsv` и `SHA256_OMITTED_ARCHIVE_FILES.tsv` содержат размер, хеш и путь каждого файла. `COMPARE_APRIL_TRUNK.json` — сравнение с `a12ba17e_shizamod_engine-main.rar` из handoff, по пути, размеру и SHA-256.
- `binaries` — материал для исследования, не файлы для установки. Перед публикацией проверьте права на сторонние SDK и наличие закрытых данных.

## Сравнение исходников

Автор указал, что архив предшествует отсечению головы и последующим патчам. Это не означает, что он представляет неизменённый оригинальный X-Ray. По сравнению с апрельским `trunk`: 7 521 файл совпал, 61 отличается, 5 есть только в новом (вложенные RAR), 7 только в старом. Значительная часть различий — камера, оружие, HUD, NPC и скриптовые методы. Даты файлов и реконструированная история не доказывают порядок установки.

Примеры отличий:
- `trunk/xr_3da/xrGame/Actor.cpp`: камера `CCameraLook2` и zoom с `tps_steady_aim`.
- `Actor_Weapon.cpp`: задержка дыхания, расход выносливости и расчёт выстрела из-за плеча.
- `CameraFirstEye.cpp`: перенос pitch при возврате из `CCameraLook2`.
- `script_game_object2.cpp`: методы позиции NPC, визуальной видимости и определения одежды; комментарии связывают часть кода с ногами от первого лица.
- `xrRender_R2/r2_R_render.cpp:136`: вызов `pHUD->Render_First()` перед `Render_Last()` в нормальной фазе. `r2.cpp` совпадает с апрельским побайтно.

## Точки дальнейшей работы

**Голова и физика.** `trunk/xr_3da/SkeletonCustom.cpp:479,497` управляет видимостью кости и маской. `xrGame/PHSkeleton.cpp:45` сбрасывает видимость при `RespawnInit`; `:66–101` применяет сохранённую маску до инициализации и восстановления физики. `xrGame/PhysicsShellHolder.cpp:284–367` сохраняет/читает физику и маску. Это точки исследования, не доказанная безопасная интеграция.

**Lua.** `xrGame/script_storage.cpp:108–143` открывает base/table/string/math/debug, но не вызывает `luaopen_package` в этом участке. Реализация package присутствует в `trunk/xrLua/src/loadlib.c`, общий список — `linit.c`; `lua.h` обозначает `Lua 5.1 (alpha) + LuaJIT 1.0.3`. Наличие реализации не доказывает регистрацию в игровом VM или совместимость с плагинами.

**Сохранения.** `trunk/xrNetServer/NET_utils.h:12,47` задаёт 8192 и строгую проверку `<` при записи. `xrGame/Level_network.cpp:194–233` вызывает `net_Save`, затем проверяет оставшееся место. Акторский путь — `Actor_Network.cpp:1693`, `GameObject.cpp:380`. Заполнение пакета около 8192 — зацепка, но не доказательство причины всех вылетов. Не менять одну константу наугад; атомарная запись и защита пакета здесь не объявляются реализованными.

**R2.** `xrRender_R2/r2.cpp:458,615–618` вызывает `D3DXCompileShader`. Текстовый поиск в `trunk` не обнаружил `__grm_test_head_id__`, `__grm_test_hide_head__`, `GRM_OGSR_POSE`, `GRM_PHYS_DIAG`, `grm_compile`, `grm_r2_cache`. Это не исключает эквивалентной логики под другими именами. Бинарный кэш из handoff — отдельная зависимость. Эффект near-focus и ранние хуки головы — разные задачи.
